# 马头琴文化资源数据库编号与文件命名规则

- 版本：1.0
- 制定日期：2026-08-19
- 对应路线：第5步“制定编号和文件命名规则”

## 1. 总体原则

- 每条资源、来源和媒体记录具有唯一、稳定、不可重复使用的编号。
- 编号只表达记录类型和顺序，不嵌入年代、地区、作者、版权或审核结论。
- 编号一经公开不得随标题、语言或页面位置变化而改变。
- 被撤回或合并的编号保留状态和指向，不分配给新记录。
- 本规则不追溯重命名现有网站文件；现有文件在第8步建立映射后再处理。

## 2. 记录编号结构

```text
MK-{类型代码}-{三位顺序号}
```

示例格式：`MK-I-001`。示例仅说明格式，不代表已存在或已确认的资源。

| 记录类型 | 类型代码 | 示例格式 |
| --- | --- | --- |
| 器物 | `I` | `MK-I-001` |
| 部件 | `CP` | `MK-CP-001` |
| 制作技艺 | `C` | `MK-C-001` |
| 制作材料与工具 | `MT` | `MK-MT-001` |
| 传承人物 | `P` | `MK-P-001` |
| 音乐与曲目 | `M` | `MK-M-001` |
| 装饰纹样 | `PT` | `MK-PT-001` |
| 历史事件 | `H` | `MK-H-001` |
| 文化场景 | `S` | `MK-S-001` |
| 参考来源 | `R` | `MK-R-001` |
| 数字媒体 | `D` | `MK-D-001` |

`MT` 是为第2步确定的“制作材料与工具”一级类型补充的代码，避免与音乐代码 `M` 冲突。

## 3. 顺序号管理

1. 每种类型独立从 `001` 顺序递增；达到 `999` 后自然扩展为四位数，不重排旧编号。
2. 编号登记后即占用；草稿删除、记录撤回或合并时也不得复用。
3. 不提前批量占号。只有创建了最小记录并写入编号登记表后才分配编号。
4. 重复记录合并时，保留一个主编号，其他编号标记“已合并”并指向主记录。
5. 资源类型确实误判且编号必须变更时，旧编号标记“已更正”，保留到新编号的永久指向。
6. 记录内容修订通过 `record_version` 管理，不在编号后增加版本号。

建议维护 `data/id-register.json`，字段至少包括：`record_id`、`resource_type`、`status`、`assigned_at`、`current_record_path`、`replaced_by`。该文件在第9步建立实际数据时创建，本步骤不提前占号。

## 4. 媒体编号与所属关系

每个媒体对象拥有独立媒体编号 `MK-D-###`，同时通过 `parent_record_refs` 与一个或多个资源记录关联。媒体编号用于数据库管理，文件名用于存储和网页交付，两者不可互相替代。

同一原始媒体生成的缩略图、网页图和下载图共享一个媒体编号，在媒体记录的 `derivatives` 中区分文件版本。

## 5. 媒体文件命名

### 5.1 基本格式

```text
{所属记录编号}-{媒体序号}-{用途或版本}.{扩展名}
```

示例：

```text
MK-I-001-01-master.tif
MK-I-001-01-web.jpg
MK-I-001-01-thumb.jpg
MK-C-001-01-web.jpg
MK-M-001-01-preview.mp3
```

媒体序号为所属记录内两位数，从 `01` 开始。一个媒体关联多个主体时，以主要著录对象编号命名，并在媒体记录中保存全部关联。

### 5.2 用途或版本词

| 标记 | 用途 |
| --- | --- |
| `master` | 经核验的保存级主文件，不直接用于网页 |
| `web` | 网页展示版本 |
| `thumb` | 缩略图 |
| `preview` | 音视频预览版本 |
| `transcript` | 音视频文字稿 |
| `poster` | 视频封面 |
| `model` | 三维模型网页版本 |

不确定是否为原始文件时不得使用 `master`，可暂用 `source` 并在媒体记录中说明来源状态。

## 6. 各类文件规则

### 图片

- 保存级文件优先保留原始格式；网页衍生图可用 `.jpg`、`.png` 或 `.webp`。
- 扩展名小写；同一文件名不得仅依靠大小写区分。
- 裁切、去背景、调色等实质处理必须生成新衍生文件并记录处理说明。

### 音频

- 保存级与网页预览文件分别管理。
- 文件名不直接写曲名、演奏者或版权状态，相关信息写入媒体字段。
- 同一曲目的不同演奏版本必须分别建立版本或媒体记录。

### 视频

- 主文件、网页版本、预览和封面分别命名。
- 字幕、文字稿与视频使用相同主体和媒体序号，增加相应版本词。

### 三维模型

- 原始制作文件和网页交付文件分开保存。
- `.fbx`、`.glb` 等格式转换需记录源文件、软件、日期和处理说明。

### 文档

- 文献扫描件、访谈记录、授权书和内部审核材料不得因文件名相近而混放。
- 含个人信息或授权凭证的文档默认不公开，访问级别在媒体记录中控制。

## 7. 目录命名

新建目录使用小写英文和连字符，不使用空格。规划目录：

```text
assets/
├── images/
│   ├── instruments/
│   ├── components/
│   ├── crafts/
│   ├── materials-tools/
│   ├── people/
│   ├── music/
│   ├── patterns/
│   ├── history/
│   └── scenes/
├── audio/
├── video/
├── models/
└── documents/
```

目录迁移在第8步执行；本步骤只规定目标规则。

## 8. 字符与格式约束

- 数据库编号只使用大写拉丁字母、数字和半角连字符。
- 新媒体文件名不使用中文、空格、括号、斜杠、全角标点或连续连字符。
- 扩展名使用小写；日期如必须写入工作文件名，使用 `YYYY-MM-DD`。
- 文件名不写“最终版”“最新版”“修改版”等不稳定词语。
- 原始文件名保存在媒体字段 `original_filename`，重命名不丢失来历。

## 9. 现有文件过渡规则

1. 第7步先盘点现有文件及其网页引用；
2. 第8步建立“旧路径—媒体编号—新路径”映射；
3. 复制并核验后再修改网页引用，不直接覆盖原文件；
4. 校验文件数量、尺寸和哈希，确认页面正常后再归档旧路径；
5. 无来源、无版权或无法识别的文件仍可盘点，但不得因此获得虚构的资源编号或公开授权。

## 10. 完成判定

- 九类资源、来源和数字媒体均有唯一代码；
- 编号生成、占用、合并、更正和版本管理规则明确；
- 图片、音频、视频、模型和文档命名规则明确；
- 原始文件、网页衍生文件和来源文件能够区分；
- 现有文件未在本步骤被重命名或移动。
