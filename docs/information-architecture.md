# 马头琴文化资源数据库信息架构方案

- 文件版本：1.0
- 制定日期：2026-08-18
- 对应路线：第3步“确定栏目与页面结构”
- 工作分支：`database-rebuild`
- 文档性质：结构规划，不包含页面开发

## 一、架构目标

网站由“一页式数字展览”逐步发展为“数据库首页＋资源库＋专题展示＋关于数据库”的学术型文化资源网站，同时完整保留现有数字展览。

本方案遵守以下边界：

1. 现有 `index.html` 和 `history.html` 在新页面验证完成前保持原状；
2. 现有长页面最终作为“马头琴文化数字展览”专题保存，不删除其中的内容和互动；
3. 第2步确定的九类数据资源保持独立，导航层可以组合展示，但不能合并或删除底层类型；
4. 本步骤只确定栏目、路径、导航和页面层级，不创建页面、不设计字段、不迁移内容；
5. 缺失的年代、来源、版权和蒙古文信息不因页面规划而被补写或推测。

## 三、导航菜单方案

### 1. 桌面端主导航

主导航保持五个固定入口：

| 顺序 | 导航项 | 目标 | 说明 |
| ---: | --- | --- | --- |
| 1 | 首页 | 数据库首页 | 展示数据库定位、数据概览、精选内容和专题入口 |
| 2 | 资源库 | 资源总览 | 展开七个浏览入口，覆盖九类数据资源 |
| 3 | 专题展示 | 专题总览 | 进入叙事型内容和原有数字展览 |
| 4 | 关于数据库 | 建设说明 | 集中展示范围、规范、来源、版权和版本信息 |
| 5 | 检索 | 全站检索 | 当前仅预留位置，实际功能在后续步骤建设 |

“资源库”展开菜单的七个浏览入口为：

1. 器物与构造：器物、部件；
2. 制作技艺与材料：制作技艺、制作材料与工具；
3. 传承人物；
4. 音乐与曲目；
5. 装饰纹样；
6. 历史事件；
7. 文化场景。

前两个入口只是导航分组，资源记录仍保留“器物、部件、制作技艺、制作材料与工具”四个独立一级类型。

### 2. 移动端导航

- 使用同样的五个一级入口，避免桌面端和移动端产生两套信息架构；
- “资源库”“专题展示”“关于数据库”采用可展开的二级菜单；
- 展开状态不改变页面地址，选择具体栏目后再导航；
- 菜单关闭、返回和当前栏目状态必须可被键盘与屏幕阅读器识别；
- 不在移动菜单中直接列出全部二级分类，避免菜单过长。

### 3. 页内辅助导航

- 资源分类页：显示当前位置、分类切换和筛选入口；
- 记录详情页：显示面包屑“首页 / 资源库 / 一级类型 / 记录名称”；
- 专题页：显示专题目录和“相关数据库记录”；
- 关于页面：使用同一组侧栏或页内目录；
- 所有页面页脚均保留“数字展览、建设说明、资料来源、版权说明、联系方式”入口。

## 五、页面类型与职责

### A. 数据库首页

回答“数据库是什么、包含什么、从哪里开始浏览”。首页只展示概览和入口，不承担全部资料的长篇叙述。

### B. 资源库总览页

回答“有哪些资源”。承载总记录数、分类数量、资源入口、精选记录和检索入口。

### C. 分类浏览页

回答“某一类资源有哪些”。承载卡片列表、分类切换、筛选、排序和分页或分批加载。

### D. 记录详情页

回答“这一条资源是什么、依据是什么、如何引用”。承载结构化字段、媒体、来源、版权、审核状态和相关记录。

### E. 专题展示页

回答“这些资源如何形成主题叙事”。专题可以引用数据库记录，但不替代记录详情页，也不把叙述性结论直接当作数据库字段。

### F. 关于与规范页

回答“数据库如何建设、资料从哪里来、如何审核、如何使用和引用”。集中呈现学术与公共服务说明。

### G. 检索结果页

回答“符合条件的资源有哪些”。承载关键词、筛选条件、结果数量、无结果提示和返回浏览入口。

## 六、现有页面和章节的去向

| 现有内容 | 目标去向 | 处理原则 |
| --- | --- | --- |
| `index.html` 整体 | `/exhibition/index.html` | 完整保留为“马头琴文化数字展览”，迁移前后做资源和交互比对 |
| `history.html` | `/history.html` | 保留现有网址，作为“历史脉络”专题入口 |
| 首页 Hero 与总览内容 | 新数据库首页的简介与专题入口 | 只选取适合首页的概览，不复制全部长篇内容 |
| `#history` | 历史专题＋历史事件记录 | 专题负责叙事，数据库记录负责结构化事实与来源 |
| `#anatomy`、`#instrument-types` | 结构与器型专题＋器物/部件资源 | 不从图像自行推测器物年代或类型 |
| `#craftsmanship` | 制作工艺专题＋技艺/材料/工具资源 | 工序与材料分别著录并关联 |
| `#heritage` | 传承人物谱系专题＋人物资源 | 师承、身份和年代必须有来源 |
| `#music-classification`、`#performance` | 音乐资源＋演奏相关专题内容 | 曲目、版本、音频和示范分层管理 |
| `#patterns` | 纹样资源＋纹样专题内容 | 名称和寓意不凭图形推测 |
| `#culture`、`#application` | 文化生态专题＋文化场景资源 | 地点、活动和人物信息缺失时标记待核实 |
| `#epilogue` | 数字展览结语 | 保留在展览专题，不作为数据库记录 |

## 七、层级与链接规则

1. 数据库记录是最小、可引用的内容单元；
2. 分类页组织记录，专题页引用记录，首页只提供入口和概览；
3. 每个记录详情页只归属一个主要资源类型，可通过关联字段连接其他类型；
4. 专题页必须链接到相关记录，记录页可反向显示相关专题；
5. 面包屑反映信息层级，不把筛选参数当成永久层级；
6. 现有 `#history` 等章节锚点在展览迁移后应继续可达或提供兼容跳转；
7. 不发布指向尚未创建页面的正式导航链接；开发期间可使用不可点击的“建设中”标识；
8. 页面标题、导航标签和网址分离管理，改中文标题时不随意改变稳定网址。

## 八、过渡与保护策略

### 阶段A：规范与数据准备（第3至第9步）

- `main` 继续发布现有数字展览；
- 新文档和后续数据改造在 `database-rebuild` 分支进行；
- 不替换根目录 `index.html`，不改变现有公开网址。

### 阶段B：数据库页面建设（第10至第15步）

- 先建设 `/database/`、记录详情和检索页面；
- 原展览继续作为默认首页，供新页面开发和对照验证；
- 新导航在工作分支测试，不提前影响线上展览。

### 阶段C：综合测试与切换（第16步）

- 将当前长页面复制并验证为 `/exhibition/index.html`；
- 验证章节锚点、图片、音频和交互与原版一致；
- 数据库首页通过测试后再替换根目录首页；
- 保留原始展示版备份分支和基线提交，确认回退方案有效后再发布。

## 九、完成判定

本步骤在以下条件全部满足时完成：

- 首页、资源库、专题展示和关于数据库四个主栏目已定义；
- 九类数据资源在导航和页面层级中均有明确入口；
- 桌面端、移动端、页内导航和面包屑原则已定义；
- 目标路径、页面类型和层级关系已定义；
- 现有 `index.html`、`history.html` 及主要章节均有保留去向；
- 过渡期间不破坏现有数字展览的策略已定义；
- 未创建或修改任何正式页面，未提前执行第4步及后续工作。
